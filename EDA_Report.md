## 5. Investigación de Problemas Específicos
- **Consistencia de CO2:** Se mencionó que `CO2_EVITO_EMITIR` contenía valores de `CO2_LOGRO_EMITIR`. Se espera que lo 'evitado' sea mayor que lo 'emitido'.
  - En **0** registros, `co2_emitido` es mayor o igual a `co2_evito_emitir`, lo que contradice la lógica esperada.
- **Inconsistencia en Pastizal:** Se mencionó que la superficie de pastizal era inconsistente.
  - Se encontraron **0** registros donde la superficie de 'pastizal_ha' es mayor que la 'total_ha', lo cual es un error.
- **Coordenadas Cero:** Se mencionó el reemplazo de ceros por NA. Aún se encuentran **1,184** registros con latitud o longitud igual a cero.
## 6. Conclusiones y Recomendaciones

### Desventajas de los Datos

1.  **Estructura Inconsistente:** La principal desventaja es la falta de un esquema unificado a lo largo de los años. Esto resultó en un dataset disperso con 246 columnas y una gran cantidad de valores nulos, haciendo necesaria una limpieza manual y la unificación de columnas.
2.  **Calidad de los Datos:** Persisten problemas de calidad, como se evidencia en:
    *   Registros donde la superficie de `pastizal_ha` supera la `total_ha`.
    *   Valores de `co2_emitido` que son mayores que `co2_evito_emitir`, contradiciendo la lógica física.
    *   Presencia de coordenadas en cero, que pueden afectar análisis geoespaciales.
3.  **Datos Faltantes:** Columnas clave como `causa`, `co2_emitido`, y las de superficie tienen un alto porcentaje de datos faltantes, lo que limita la representatividad de cualquier análisis sobre ellas.
4.  **Tipos de Datos Mixtos:** Muchas columnas numéricas fueron almacenadas como texto (`object`), requiriendo una conversión cuidadosa que resultó en pérdida de datos por formatos inválidos.

### Áreas de Mejora

1.  **Estandarización de Nombres de Columnas:** Antes de unir los datos anuales, se debería aplicar un script para renombrar las columnas a un estándar único. Esto eliminaría el problema de las 246 columnas.
2.  **Validación de Datos en Origen:** Implementar reglas de validación al momento de la captura de datos. Por ejemplo, la suma de las superficies parciales no puede exceder la superficie total. Las coordenadas deben estar en un rango geográfico válido para México.
3.  **Imputación de Datos Faltantes:** Para variables importantes con datos faltantes, se podrían explorar técnicas de imputación (ej. media/mediana por estado/año, o modelos más complejos como k-NN) si se determina que es metodológicamente apropiado.
4.  **Enriquecimiento de Datos:** Cruzar los datos con fuentes externas. Por ejemplo, usar la `CVE_EDO` para unir con datos socioeconómicos o climáticos del INEGI podría revelar nuevos insights.

### Recomendaciones

1.  **Usar con Precaución:** Cualquier análisis debe ser consciente de las limitaciones. Los resultados de las variables con muchos datos faltantes o inconsistencias (`co2_emitido`, `pastizal_ha`) deben interpretarse como exploratorios y no definitivos.
2.  **Priorizar Columnas Robustas:** Para modelos predictivos o análisis inferenciales, es más seguro centrarse en las columnas con mayor completitud y consistencia, como `anio`, `estado` y `total_ha`.
3.  **Documentar el Proceso de Limpieza:** El trabajo ya realizado para limpiar y unificar los datos es valioso. Este proceso debe ser documentado en un script reutilizable para garantizar la reproducibilidad y facilitar futuras actualizaciones.
4.  **Análisis por Segmentos:** Dado que la calidad de los datos puede variar por año, considere realizar análisis por separado para periodos de tiempo donde los datos son más consistentes antes de agregar los resultados.
